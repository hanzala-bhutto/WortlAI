# Feasibility: 012 - Lexical graph tables + citation-validated LLM edge extraction

- **Issue**: #12 - **Phase**: 2 - **Date**: 2026-08-01 - **Author**: Claude (reviewed by Hanzala)

## Goal
Stand up the SQLite lexical graph the Curriculum agent (#16) walks: a `words` **node** table (the graph has nowhere to point without one - see below), typed-edge `word_links` (IN_FAMILY, COLLOCATES_WITH, GOVERNS, SYNONYM, ANTONYM), and `error_pattern_links` (error-type -> affected words). Structural family edges are derived **deterministically** from #9's glossary parse; relational edges (collocation, synonym, antonym, government) come from **LLM extraction with a citation gate** - every LLM edge must quote a span that is found verbatim in the real corpus and contains both endpoint words, or it is dropped, never stored. User-visible outcome: `/graph-check` passes (zero uncited LLM edges by construction), and a family walk for a sample verb returns its real family.

## Investigation (code actually read, not assumed)

- **There is no `words` table.** #9's `WordRecord`s were only ever written to Qdrant's `vocab` collection (#11 `qdrant_store.index_records`); nothing persists them to SQLite. But `word_links` needs node rows to FK against, and `/graph-check`'s check 1 audits "orphan words with no topic/chapter" - which presumes a node table with those columns. No later Phase 2 issue creates it either: #13 says "into the words store" as if it exists, #14 assumes "word states." **Decision (confirmed with Hanzala 2026-08-01): #12 owns the `words` table.** It persists the same `WordRecord` fields #9 already produces; #13 (Goethe) and #14 (FSRS `word_states`) hang off it later.
- **`WordRecord` carries no example-sentence field.** `glossary_parser.py` captures lemma/article/plural/`VerbForm` but discards the trailing `_rest` (the parenthetical usage examples). So the A1 glossary contributes almost no citable sentence material - it is a word list, not a sentence corpus.
- **The real citation corpus is #10's output.** `vision_extract.py` produces `RedemittelSet.source_text` / `RedemittelPhrase.phrase` and `GrammarBox.content` / `.source_text` - verbatim textbook spans (the spike in docs/feasibility/010 confirmed verbatim transcription incl. umlauts). These are the legitimate spans an LLM relational edge can cite. Government (prep+case) in particular lives in grammar boxes ("sich freuen auf + Akk"), not in the A1 glossary at all.
- **There is no `ErrorPattern` entity.** `ErrorLog.error_type` is a dotted taxonomy string ("grammar.case.dative"); "error patterns" are those strings aggregated, not a table. So `error_pattern_links` keys on the `error_type` string -> `word_id`, matching how the rest of the code already treats error types (`queries.error_counts_by_type`). It is populated later (Corrector/Curriculum, #16/#26); #12 lands the table + writer, not a populated graph.
- **Reuse, don't rebuild.** `LLMProvider.complete()` already gives the Groq->NIM chain, retry/backoff, Langfuse tracing, and Pydantic-friendly JSON handling (`vision_extract.py` is the template for a parse-validate-or-drop extraction pass). Alembic migrations run at startup via `learner/migrate.py`; the new tables are one migration on the existing `Base`.

## Approach options

1. **Recommended - two provenance tracks behind one `word_links` table, node table owned here.**
   - **`words` node table**: persist `WordRecord`s (lemma, lemma_raw, pos, article, plural, flattened `VerbForm`, level, translation_en, chapter, chapter_title, topic, `source='glossary'`, source_page, needs_review). Unique `(lemma, pos, level)` to dedupe re-ingests.
   - **`word_links`**: `from_word_id`, `to_word_id` (FK `words`), `edge_type` (the 5 types), `source ∈ {deterministic, llm}`, `citation TEXT NULL`, unique `(from_word_id, to_word_id, edge_type)`. A DB **CHECK** enforces `source='llm' -> citation IS NOT NULL AND citation != ''` so an uncited LLM edge is unwritable at the storage layer, not just discouraged - `/graph-check`'s check 2 then returns zero by construction, and the app validator (below) is defence in depth, not the only guard.
   - **Deterministic track -> IN_FAMILY only.** Highest-precision signal is already in the parse: separable verbs (`mit|sprechen`) carry `verb.prefix` + `infinitive`, so `mitsprechen -> sprechen` is a certain family edge. Conservative shared-stem matching (min stem length, same-or-related pos) adds noun<->verb families (ziehen/umziehen/Umzug), flagged for `/graph-check`'s family-sanity sample rather than trusted blind. `source='deterministic'`, citation NULL (allowed - the derivation rule *is* the provenance).
   - **LLM track -> COLLOCATES_WITH / SYNONYM / ANTONYM / GOVERNS.** Feed the model a delimited data block (guardrail 6) of real corpus spans (#10 Redemittel/grammar text; glossary example text once retained) plus the candidate words in them, ask for edges each quoting its source span. **Citation gate:** an edge is kept only if (a) citation non-empty, (b) the citation is found **verbatim** in the actual corpus text we passed in (not merely asserted), and (c) the citation contains both endpoint lemmas (spaCy `de_core_news_sm` lemmatization so an inflected form counts). GOVERNS additionally must parse to `prep+Case` (e.g. `auf+Akk`) or it is dropped (`/graph-check` check 5). Anything failing is dropped, Pydantic-validate-or-retry-once-then-drop per guardrail 1. This is strictly stronger than the issue's literal "carries a citation" and is what makes the anti-hallucination rule real.
   - **`error_pattern_links`**: `error_type` (string) -> `word_id`, `note`, `created_at`. Table + writer land now; population is Phase 3.
2. **`word_links` stores bare lemma strings, no node table** - rejected: nothing to audit orphans against, no place for `word_states` (#14) or Goethe coverage (#13) to attach, and the FK that guarantees an edge points at a real word disappears. Smaller diff now, larger debt in three downstream issues.
3. **Trust the LLM's citation as-is (non-empty check only)** - rejected: that is exactly the hallucinated-edge failure guardrail 5 names. A model will happily emit a plausible German sentence that never appeared in the corpus; without the verbatim-in-corpus + both-lemmas-present check, "cited" means nothing.

## Risks & unknowns

- **Thin citation corpus until #10 output is on disk.** LLM relational edges are only as rich as the real spans available to cite; the A1 glossary alone barely has sentences. Mitigation: draw citations from #10's `RedemittelSet`/`GrammarBox` records (their `source_text`/`content`), and extend `glossary_parser.py` minimally to retain the parenthetical example it currently drops as an `example_de` field (small, additive). If #10 records are not yet ingested at implementation time, IN_FAMILY (deterministic) is the must-ship core and LLM edges ship against whatever corpus exists and grow as #10 lands - the schema and gate do not change.
- **Family false positives from stem matching** (e.g. `Recht`/`recht`/`richten`). Mitigation: require a longer shared stem, keep separable-prefix edges (certain) separate from stem-guess edges, and lean on `/graph-check` check 4 to surface bad clusters for human eyes rather than pretending precision we do not have.
- **Untrusted content (guardrail 6):** corpus spans are exactly the textbook text CLAUDE.md flags - imperatives like "Ruf mich an!" must stay data, never instruction. The extraction prompt keeps spans in a delimited block, pins policy server-side, and scans for instruction-like patterns (the `vision_extract.py` precedent).
- **Idempotent re-ingest:** `/ingest` reruns must not duplicate edges or nodes. Unique constraints on both tables + upsert-by-natural-key handle it; deterministic edges are safe to recompute, LLM edges are re-validated not blindly re-inserted.

## Free-tier impact
LLM extraction is a one-time **offline batch** (a handful of hundred `LLMProvider.complete()` calls over corpus chunks, well under Groq's ~1,000 req/day), on the normal Groq->NIM text chain - no vision model needed here. Zero Whisper/audio-seconds (ingestion, not the voice loop). Each call gets a Langfuse trace on the self-hosted instance - no metered quota. Extraction derived from copyrighted Klett pages stays in `backend/data/` (gitignored), same rule as #9/#10.

## Effort estimate
L (1-2 days). Cost drivers: the Alembic migration + `words` persistence, deterministic family derivation with its precision guards, the LLM extraction prompt (Langfuse-managed) + Pydantic edge schema, the citation validator (verbatim-in-corpus + both-lemmas-present, spaCy lemmatized), wiring `/graph-check`'s six checks to the real tables, and tests covering the drop paths (uncited edge rejected, non-verbatim citation rejected, malformed GOVERNS rejected) - not just the happy family walk.

## Verdict
**GO.** Deterministic IN_FAMILY edges are certain from the existing parse; the citation gate (verbatim-in-corpus + both-lemmas + DB CHECK) makes the anti-hallucination rule enforceable at the storage layer, so `/graph-check` passes by construction rather than by hope. `#12` owns the `words` node table; `error_pattern_links` lands as a table + writer, populated in Phase 3. The one dependency to watch is citation-corpus richness (#10 output) - it changes how *many* LLM edges land, not *whether* the design is sound.
